# Repository agent instructions

- Implement and test the work explicitly approved by the project owner. Creative direction, architecture approval, technical review, and milestone planning are coordinated separately by the owner.
- Read CONTINUATION.md, the README, roadmap, and relevant design, architecture, and storyboard sections before editing. The storyboard and timings are flexible planning guides; respect approved concepts and scope. The roadmap defines approval boundaries. Treat architectural proposals and storyboard choices as provisional until reviewed.

- M2, M3 and owner-approved M4a are merged. Issue #10 authorizes M4b in two stages. Complete the separate static staging review before implementing the animation or integrating it into the production deck. Use the original approved concept images as direct references whenever available. M4 remains open pending approval of slide 7, and M5 requires separate authorization.
- Commit, push, and create remote branches only when explicitly authorized. Keep employer information, secrets, and private credentials out of code, docs, assets, examples, and tool output.

## Implementation standards

- Use readable TypeScript with explicit types at module boundaries and keep changes scoped. Reuse existing scene, rendering, and control APIs where they fit. Keep educational model state independent of Reveal.js and rendering details.
- Keep rendering repeatable using stable seeds and inputs. Keep scene initialization and cleanup predictable, including under rapid navigation, revisits, restart, and backward seeking. Release scene-owned timelines, listeners, and other resources on exit.
- Keep slide navigation separate from animation and interaction. Preserve keyboard navigation and presenter affordances. Review any binding against the installed Reveal.js version, browser behavior, and focus in interactive controls.
- Bundle production dependencies, fonts, and media locally. Keep runtime operation independent of internet access, remote APIs, and CDNs. Use synthetic classroom data and visibly label toy cryptography. Use internationally relatable examples and neutral currency units, with no demographic-specific localization or samosas. Use Alice, Bob, and Charlie for the recurring cast. Reserve Eve for eavesdroppers and Mallory for explicitly malicious adversaries.
- Verify teaching claims against appropriate primary references. State relevant assumptions and limits in speaker notes. Use original illustrations and record font and asset licenses. The real three-Spider-Man meme on slide 5, Sam Altman likeness satire on slide 22, and brand marks on slide 24 are owner-approved creative exceptions, not grants of redistribution rights; verify provenance and rights, use a documented local offline asset route if needed, and do not commit unauthorized third-party media. Do not attribute the fictional RAM joke as a real quotation. Use real SHA-256 and real nonce search on 14–15; use verified or explicitly illustrative hashes on other slides.
- Run the checks relevant to the approved work. Use deterministic tests for state transitions. Develop and rehearse in desktop Firefox. Run the shared Playwright suite with Firefox as the primary automation target and Chromium for compatibility. Report manual checks, unverified behavior, and failures explicitly.
